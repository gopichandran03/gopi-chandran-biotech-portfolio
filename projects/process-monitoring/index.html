02 · Quality & process monitoring

A process in control
is not the same as a process in spec.

A working demonstration of statistical process monitoring: how control limits are derived, what a run rule detects that a single out-of-limit point misses, and why capability and control answer two different questions. Built because the distinction matters in any environment where a measurement decides whether material moves forward.

Interactive · synthetic dataPython + browser demoTeaching demonstrationNot a validated method
Read this first: every number in this demonstration is synthetically generated, in your browser or by the Python script in this repository. Nothing here is real process data, from any laboratory or employer. This is an educational illustration of descriptive process monitoring - it is not a validated analytical method, not a GMP release-control strategy, and not suitable for making decisions about real material.

01 · Why

The question behind every in-process measurement

You took a measurement. It is different from last time. Is that the process changing, or is that just what this process looks like?

Almost every operational decision in a laboratory or manufacturing environment is a version of that question. Viable cell density came back lower than yesterday. A pH reading drifted. A confluence estimate is off. The instinct is to react to the number; the discipline is to ask first whether the number is outside what the process does naturally.

Common-cause variation

The irreducible noise of a stable process - pipetting, sampling, instrument precision, biological variability between flasks. It is always there. Reacting to it makes the process worse, because you adjust in response to noise.

Special-cause variation

Something genuinely changed - a new reagent lot, an incubator drifting, a contamination event, a different operator technique. This is what you want to detect, quickly, and act on.

What statistical process control actually gives you: a defensible, pre-agreed rule for telling those two apart, set before you see the result - so the decision is not a judgement call made under pressure about a number you already dislike.
02 · The statistics

Where the limits come from - and what they are not

A Shewhart control chart plots a measurement in time order against limits derived from the process's own behaviour during a stable baseline period.

Control limits

Calculated as the baseline mean ± 3 standard deviations of the baseline data. They describe what this process does. They come from the data and nothing else.

UCL = x̄ + 3s
CL  = x̄
LCL = x̄ - 3s

Specification limits

The range the material must be in to be acceptable. They come from requirements - a protocol, a product specification, a regulatory filing. They have nothing to do with the data you collected.

These are different things and they are not interchangeable.

Why ±3 standard deviations? Under an approximately normal, stable process, about 99.7% of observations fall inside that band, so a point outside is a roughly 1-in-370 event - rare enough to be worth investigating, common enough that you are not blind to a real shift. It is a deliberate trade between false alarms and missed signals, not a law of nature.

The error to avoid: drawing specification limits on a chart and calling the process "in control" because points sit inside them. A process can be wildly unstable and still inside spec (you are getting lucky), or perfectly stable and entirely outside spec (you are consistently making the wrong thing). Slides 3 and 5 separate the two.

04 · Run rules

What a single out-of-limit point misses

A point beyond 3 SD is the obvious signal, and it is also the least sensitive one. Small sustained shifts - exactly the kind a drifting incubator or a new reagent lot produces - rarely throw a single point that far. They show up as patterns.

RulePatternWhat it typically means
1Any single point beyond 3 SD from the centre lineA gross excursion - a bad sample, a transcription error, a real and large event
2Nine consecutive points on the same side of the centre lineThe process mean has moved. Nothing is out of limits; the centre has shifted
3Six consecutive points steadily increasing or decreasingDrift - calibration, temperature, reagent degradation, cell passage effects
4Two of three consecutive points beyond 2 SD on the same sideAn emerging shift, caught earlier than rule 1 would catch it

These are a subset of the Nelson rules, which in turn descend from Western Electric's handbook. In clinical laboratory practice the closely related Westgard rules play the same role for assay quality control. The arithmetic is simple; the discipline is agreeing which rules apply before you run the samples.

The cost of more rules

Every rule you add increases sensitivity to real change and increases false alarms. Run eight rules on a stable process and you will investigate things that never happened - and teach everyone to ignore flags.

The cost of fewer rules

Run only rule 1 and a one-sigma shift can persist for dozens of runs unnoticed. In a cell culture context that could be an entire expansion carried out on a quietly altered process.

The real skill is not computing limits - any script does that. It is choosing a rule set proportionate to the cost of a false alarm versus the cost of a missed shift, and then holding to it.
05 · Capability

Control and capability answer different questions

Once a process is stable, a second and separate question arises: is the thing it stably does actually acceptable?

Is it in control?

Stability over time. Answered by the control chart. Uses only the process data.

If no: capability indices are meaningless, because there is no single stable process to describe.

Is it capable?

Does the stable process fit inside the specification? Answered by capability indices, which need the spec as an input.

Cp  = (USL - LSL) / 6s
Cpk = min(USL - x̄, x̄ - LSL) / 3s

Cp asks whether the spread could fit in the window. Cpk asks whether it fits where the process actually sits. A process can have excellent Cp and poor Cpk simply by being off-centre - the variability is fine, the aim is wrong, and those have completely different fixes.

SituationIn control?Capable?What to do
Stable, comfortably inside specYesYesMonitor. Change nothing.
Stable, consistently off-centreYesNo - aimRe-centre the process. Do not touch variability.
Stable, spread wider than the windowYesNo - spreadReduce variability, or revisit whether the spec is right.
Unstable, currently inside specNoUnanswerableFind the special cause first. Capability numbers here are fiction.
Order of operations: stability before capability, always. Computing Cpk on an out-of-control process produces a confident number that describes nothing.
06 · Real systems

What would have to be different in a regulated environment

I want to be precise about the distance between this demonstration and a real quality system, because that distance is the point of the slide.

This demonstrationA regulated in-process monitoring programme
Synthetic numbers generated on page loadData from qualified instruments, under data-integrity controls, attributable and audit-trailed
Limits recomputed on the fly as you move slidersLimits established from a defined baseline, documented, version-controlled and changed only under change control
Rule set switchable in a dropdownRule set pre-specified in an approved procedure before data is collected
A flagged point is a coloured dotA flagged point opens a documented investigation with defined responsibilities and timelines
Script in a public repositoryValidated software, qualified for intended use, with specification, testing and traceability
No consequenceMaterial disposition - a decision about whether product moves forward

Where I have actually worked with this thinking

In mammalian cell culture support at UMBC - HEK293 and HTB-182 maintenance - the relevant discipline is less about charting than about the conditions that make charting meaningful: consistent aseptic technique, contamination-conscious handling, equipment readiness checks, and documentation good enough that an unusual observation can be traced to something. A control chart over badly collected data is a confident-looking artefact with nothing underneath it.

Honest statement of my position: I have the statistical literacy demonstrated here and hands-on cell culture experience where consistency matters. I have not owned a validated SPC programme in a GMP environment, and this page does not claim otherwise.
07 · Limits

What this demonstration assumes, and where that breaks

  • Independent observations. Real in-process measurements are often autocorrelated - today's reading depends on yesterday's. Autocorrelation inflates false alarms badly, and the standard chart is the wrong tool; a time-series or EWMA approach fits better.
  • Approximate normality. Many bioprocess measurements are skewed or bounded (counts, percentages, titres). Limits computed as mean ± 3 SD on a skewed distribution are asymmetric in reality but drawn symmetric here. A transformation or an attribute chart is often more appropriate.
  • A genuinely stable baseline. The limits are only meaningful if the baseline period was in control. If the baseline already contained a shift, the limits are inflated and will hide the next one.
  • Individual measurements. This is an individuals chart. With rational subgroups an X-bar and R or S chart separates within- from between-subgroup variation, which is usually more informative.
  • One variable at a time. Real processes have many correlated parameters; monitoring each independently multiplies false alarms and misses multivariate drift.
Why list the weaknesses: because a portfolio piece that shows only what a method does is less useful than one that shows where it fails. If I brought this chart to a real process, these are the five things I would check before trusting it.
08 · Code & reading

Run it yourself

The browser demo above is self-contained. The repository also contains a Python implementation that does the same analysis on a generated dataset and writes out a summary table and a chart - useful if you want to inspect the arithmetic rather than the interaction.

git clone https://github.com/gopichandran03/gopi-chandran-biotech-portfolio.git
cd gopi-chandran-biotech-portfolio
python3 -m pip install -r requirements.txt
python3 workflows/quality_control/process_monitor.py --fault shift --size 1.5 --seed 7

It prints the baseline statistics, the control limits, every rule violation with the rule that caught it, and capability indices against specification limits you pass on the command line. Add --plot out.png for the chart.

Background reading

  • Shewhart control charts and the common-cause / special-cause distinction - W. A. Shewhart, Economic Control of Quality of Manufactured Product (1931); W. E. Deming's later work on reacting to noise ("tampering").
  • Run rules - L. S. Nelson, "The Shewhart Control Chart - Tests for Special Causes," Journal of Quality Technology 16(4), 1984. Descended from the Western Electric Statistical Quality Control Handbook (1956).
  • Westgard rules for clinical laboratory QC - J. O. Westgard et al., "A multi-rule Shewhart chart for quality control in clinical chemistry," Clinical Chemistry 27(3), 1981.
  • Process capability - standard treatment in D. C. Montgomery, Introduction to Statistical Quality Control.
  • Regulatory context for in-process controls and data integrity - ICH Q8-Q10 on pharmaceutical development, quality risk management and quality systems; relevant GMP data-integrity guidance.
